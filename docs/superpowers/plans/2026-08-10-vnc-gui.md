# VNC GUI (Display tab) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Surface the merged VNC desktop feature (PR #215, daemon proto v6) in the Tauri GUI: a "Display" tab on the sandbox detail page that embeds the live KasmVNC desktop in-app, with enable/disable, restart guidance, open-in-browser, and a `--vnc` toggle in the create wizard.

**Architecture:** The GUI backend gains a `vnc_set` command (mechanical copy of `usb_revoke` through the `DaemonApi` seam — the daemon-side `DaemonRequest::VncSet` already exists, **no daemon/proto changes**). Because WebView2 (Chromium) blocks credentials embedded in iframe URLs, in-app embedding goes through a small **auth-injecting loopback proxy** inside the Tauri process (`vncproxy.rs`): it accepts plain HTTP on an ephemeral `127.0.0.1` port, injects the `Authorization: Basic` header parsed from the daemon's credentialed `vnc_url`, and splices bytes — including the websocket upgrade — to the daemon's VNC relay. The frontend gets a pure presentation module mirroring the CLI's `url_or_reason` honest-state case analysis, a `DisplayTab` component, and a create-wizard checkbox.

**Tech Stack:** Rust (std::net sync sockets + threads — the crate's existing precedent; NO tokio, NO new deps), Tauri 2 commands, React + TypeScript, vitest + Testing Library, Playwright (mock-backed), GUI dogfood harness (python).

## Global Constraints

- **No daemon or wire-protocol changes.** `DAEMON_PROTO_VERSION` stays 6; `DaemonRequest::VncSet { name, enabled }` and the four `SandboxDetail` vnc fields already exist (`crates/izba-core/src/daemon/proto.rs`).
- **Credential discipline (spec 2026-08-09 §6/§10):** `vnc_url` carries the plaintext password in its userinfo. In the GUI it may reach the frontend only via `SandboxDetail` (already does) and may be *used* only by the Display tab's explicit "Open in browser" / "Copy URL" actions. It must never be logged (Rust or JS), never rendered as visible text, and never appear in any list/overview surface. The embed path keeps the password out of the iframe URL entirely (the proxy injects it Rust-side).
- **Unauthenticated-proxy accepted risk:** while the embed proxy runs, any local process can reach the desktop through it without credentials. This is the same single-user-desktop tradeoff already accepted for `izba vnc open`'s argv (see `crates/izba-cli/src/commands/vnc.rs` `platform_open` doc comment) and MUST be doc-commented at the proxy and noted in the spec addendum (Task 10). Mitigations that ARE required: bind `127.0.0.1` only, run the proxy only while a Display tab is embedding, stop it on tab unmount and sandbox switch.
- **Honest-state mirror:** the Display tab's case analysis must mirror `url_or_reason` + the two warnings in `crates/izba-cli/src/commands/vnc.rs:188-232` exactly — `vnc_url` presence is checked FIRST (a live desktop after `vnc off` is real and gets shown, with the "disabled in config" warning), then not-enabled, then not-running, then restart-required.
- **TS mirrors Rust serde output verbatim:** new `SandboxDetail` fields are snake_case (`vnc`, `vnc_running`, `vnc_url`, `vnc_restart_required`), matching `app/src/lib/types.ts` convention (`mem_mb`, `restart_required`).
- **Tabs are never conditionally hidden** (convention, `app/src/test/detail.test.tsx:168-173`): the Display tab shows even when VNC is off — the tab is where a user learns the feature exists. Only the content branches.
- **Every Tauri command needs all four legs:** `*_core` in `commands.rs`, `#[tauri::command]` wrapper in `lib.rs`, the `generate_handler![]` registration, AND a `dispatch` arm (`lib.rs:565+`) — the dogfood bridge only reaches commands through `dispatch`.
- **Unit tests never bind listeners without a guard:** any test that binds a TCP listener must runtime-skip on `std::io::ErrorKind::PermissionDenied` (sandboxes deny bind) — see the pattern in `crates/izba-core/src/vsock.rs` `full_connect_via_listener`.
- **Gates per task:** from `app/`: `npm run lint && npm test && npm run build` for frontend tasks; from `app/src-tauri`: `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` for Rust tasks. The root workspace is untouched by this plan (app is excluded from the workspace), but Task 7 touches `app/src-tauri/src/views.rs` which embeds izba-core types — still app-gate only.
- **No new dependencies.** `base64` is already in `app/src-tauri/Cargo.toml`; sockets are `std::net` + `std::thread` (precedent: `app/src-tauri/src/bin/headless.rs`, `daemon.rs:314`).

### Task 2: `vncproxy` module — auth-injecting loopback proxy

**Files:**
- Create: `app/src-tauri/src/vncproxy.rs`
- Modify: `app/src-tauri/src/lib.rs` (add `mod vncproxy;` only — commands come in Task 3)

**Interfaces:**
- Consumes: nothing from other tasks. `base64::engine::general_purpose::STANDARD` (dep exists; see `daemon.rs`/`lib.rs` for the crate's existing base64 import style).
- Produces (Task 3 relies on these exact signatures):
  - `pub struct ProxyTarget { pub port: u16, pub authorization: String }` with `PartialEq`
  - `pub fn parse_vnc_url(url: &str) -> anyhow::Result<ProxyTarget>`
  - `pub struct VncProxy` with `pub fn start(target: ProxyTarget) -> anyhow::Result<VncProxy>`, `pub fn port(&self) -> u16`, `pub fn target_matches(&self, t: &ProxyTarget) -> bool`, and a `Drop` impl that stops the accept thread.

**Why this exists (must be in the module doc comment):** WebView2 (Chromium) refuses credentials embedded in subresource URLs, so the Display tab cannot iframe the daemon's credentialed `vnc_url` directly. This proxy accepts credential-less HTTP from the app's webview on an ephemeral loopback port, injects the `Authorization: Basic` header server-side, and splices to the daemon's VNC relay — including the websocket upgrade (KasmVNC gates HTTP *and* ws behind Basic auth). **Accepted risk (single-user desktop, same class as `izba vnc open`'s argv exposure):** while running, any local process can reach the desktop through this port without credentials; it binds 127.0.0.1 only and runs only while a Display tab is embedding.

**Design (implement exactly this):**
- `parse_vnc_url`: input is the daemon's fixed shape `http://<user>:<password>@127.0.0.1:<port>/` (built at `crates/izba-core/src/daemon/server.rs` ~line 820; password alphabet is `[A-Za-z0-9]`, no percent-encoding concerns). Strip the `http://` prefix, split userinfo at the LAST `@` before the first `/`, split host:port, `bail!` with a clear message on any malformed shape. `authorization` = `format!("Basic {}", STANDARD.encode(format!("{user}:{password}")))`. **Never include the input URL or password in error messages** (credential discipline).
- `rewrite_request_head(head: &str, authorization: &str) -> anyhow::Result<(String, bool)>` (private but unit-tested): takes one HTTP request head (request line + headers, no trailing empty line needed), returns the rewritten head and `is_upgrade`. Rules: drop any client-sent `Authorization` header; detect upgrade via an `Upgrade:` header whose value case-insensitively contains `websocket`; for upgrades keep `Connection`/`Upgrade` headers as-is; for non-upgrades drop `Connection`/`Keep-Alive` headers and append `Connection: close` (this makes the one-request-per-connection splice correct: the relay closes after the response, the browser opens a fresh connection per request — negligible on loopback); always append the `Authorization` header. Preserve request line and all other headers byte-for-byte, `\r\n` line endings.
- Connection handling: accept loop on a `TcpListener` bound to `127.0.0.1:0`; each connection gets a thread that (1) reads until `\r\n\r\n` (cap 64 KiB, drop oversized), (2) rewrites the head, (3) connects to `127.0.0.1:{target.port}`, writes the rewritten head + any body bytes already read past the head, then (4) bidirectional raw splice: one thread copies client→upstream, the current thread copies upstream→client; on either EOF/error, `shutdown(Shutdown::Both)` both sockets and join. This one shape serves plain requests AND websockets (after an upgrade the connection is a raw byte pipe anyway).
- Shutdown: `VncProxy` holds the listener's local port, an `Arc<AtomicBool>` stop flag, and the accept thread's `JoinHandle`. `Drop` sets the flag, unblocks `accept` by opening a throwaway `TcpStream::connect` to its own port, and joins the accept thread (in-flight connection threads are detached and die with their sockets — document this). No logging of request contents anywhere.
